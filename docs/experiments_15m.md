# 15m 进场机会实验（2026-08-01 ~ 10-31）

目标：在不放弃 0.94 上限的前提下，找出能**增加进场次数**、且样本外仍然成立的规则变体。

- 数据：`data/dataset`（BTC 15m，1 秒 + 5 秒拼接）
- 成本：官方费用 `0.07`、滑点 `0.005`、10 USDC/笔
- 复现：`python -m src.research.experiments_late_window`
- 产物：`data/research/experiments_15m/variants.{json,csv}`

## 为什么会缺进场

基线在 8–10 月扫描约 8,800 个市场，只有 248 笔成交；**92% 的跳过是 `price_too_high`**：
热门方在第一次跨过 0.90 后，到确认那一刻已经涨到 0.94 以上，规则直接放弃。

## 结论

1. **最有效的杠杆是降低触发阈值，而不是改入场窗口。**
   阈值 0.88 把验证集成交从 56 笔提高到 104 笔（约 1.9 倍），验证净利 +50.15（基线 +29.23），
   t=2.68；0.89 更保守（84 笔，+43.07，t=2.81）。0.88–0.89 是当前证据最稳的区间。
2. **软确认 0.88 + 触发 0.88** 是第二选择：验证 117 笔、+56.43、t=2.60，
   代价是训练集 t 从 2.99 降到 2.05。
3. **重新武装**单独使用只增加约 12% 的交易，验证略好于基线，可以作为附加项。
4. **上限 0.95** 在验证集表现很好（+47.41，t=4.41），但训练集 t 只有 1.81；
   文档也提醒 0.94–0.95 档价差偏弱，不建议单独放宽。
5. **「超上限后等回撤」是陷阱**：它确实把成交从 248 提到 298–658，但价差从 +4.94pp
   掉到 +1.65~+2.70pp，ROI 和 t 都显著恶化。价格跌破上限本身就是「热门方变弱」的信号，
   不是折价买入的机会。
6. **加宽窗口（120/180s）全部为负**：更早的突破预测力不足；最后 60 秒是有效区间。
7. **取消确认**能带来 1,451 笔，但 ROI 掉到 +1.23%，t=1.76，且 0.01 滑点下风险更大。

## 已应用

15m 实盘默认已改为 **阈值 0.88**，其余保持 60s / 10s 确认 / 0.94 上限 / 10 USDC；
GTD 按 `单笔金额 ÷ 限价` 换算股数（不少于 5 股）。

## 建议

- 若目标是「进场机会更多」：把 15m 的 `ENTRY_THRESHOLD` 从 0.90 调到 **0.88**（或 0.89 偏保守），
  其余参数保持 60s / 10s / 0.94 不变。
- 这是**同一份 8–10 月数据上的选择**，虽然做了训练/验证切分，仍不是完全独立的样本。
  上线前建议先纸面跑 1–2 周，或用 11 月数据跑一次 `validate`。
- 不建议单独放宽上限或加宽窗口；也不要采用「等回撤」规则。
